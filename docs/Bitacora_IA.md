# Bitácora de IA — completar con registro real del equipo

Esta plantilla resume los objetivos de las iteraciones usadas para construir el borrador. Para una entrega académica honesta, el equipo debe agregar/corregir los prompts reales, las respuestas que revisó, los errores que detectó y sus decisiones humanas. No debe afirmarse que se ejecutaron pruebas o se aprobaron decisiones si no ocurrió.

| Iteración | Objetivo | Respuesta útil | Supuesto/riesgo | Decisión humana requerida |
|---|---|---|---|---|
| 1 | Comparar Transaction Script, Table Module y Domain Model con evidencia U2 | Domain Model candidato por reglas interrelacionadas | Debe compararse con todas las historias | Revisar y aceptar o cambiar patrón |
| 2 | Proponer entidades, Value Objects, Aggregates y eventos | Reservación, Habitación, Estancia, Cuenta, Consumo | Candidato no equivale a decisión aprobada | Validar contra glosario y reglas |
| 3 | Proponer Service Layer, Repository y Unit of Work | Servicios por caso de uso, interfaces pequeñas | Falta implementación real de persistencia | Revisar límites y errores |
| 4 | Generar diagramas | Borradores de dominio y secuencia | Verificar consistencia entre UML, código y U2 | Corregir nombres/relaciones y registrar cambios |
